# 기능 작업 흐름: $ARGUMENTS

서브에이전트끼리는 서로 부를 수 없으므로 **메인 세션(이 스킬)이 순서대로 부른다.**
**각 단계 사이에 사용자 확인을 받는다. 자동으로 다음 단계로 넘어가지 않는다.**
기능 이름이 비어 있으면 먼저 사용자에게 묻는다.

## 1. 구현 설명 — `developer` 에이전트
- `developer`를 불러 "$ARGUMENTS" 구현 방법을 **단계별 설명 + 붙여넣을 코드 조각(파일 경로 포함) + 왜 이렇게 짰는지**로 받는다. 이 단계에서는 파일을 수정하지 않는다.
- 결과(한 일 / 바꾼 파일 / 남은 문제 / 넘길 것)를 사용자에게 보여 주고 묻는다:
  **"직접 작성하시겠어요, 아니면 '작성해줘'라고 하시겠어요?"**
  - 직접 작성: 사용자가 끝났다고 할 때까지 기다린다.
  - "작성해줘": `developer`를 다시 불러 파일을 작성하게 한다.
- 다른 팀원 담당 파일이 포함되면 그 팀원에게 공유하라고 알린다.

## 2. 테스트 — `tester` 에이전트 (사용자 확인 후)
- `tester`를 불러 테스트 케이스와 코드 조각을 보여 주게 한다(developer가 넘긴 "테스트 지점" 포함).
- 사용자가 "작성해줘"라고 하면 `tests/`에 작성하고 `pytest`를 실행한다.
- **실패하면** 원인과 담당 파일을 보고하고, 사용자 확인 후 **1단계(developer)로 돌아간다.** 테스터는 앱 코드를 고치지 않는다.
- 통과하면 결과를 사용자에게 보여 주고 다음 단계 진행 여부를 묻는다. 결과를 `docs/test-log.md`에 남길지(`/scenario-test` 형식)도 묻는다.

## 3. 검수 — `qa` 에이전트 (사용자 확인 후)
- `qa`를 불러 요구사항·시나리오·안전·시연 안정성을 검수하게 한다(코드는 고치지 않음).
- **실패/위험** 항목이 있으면 심각도 순으로 사용자에게 보여 주고, 고칠지 묻는다. 고치기로 하면 1단계로 돌아간다.

## 4. 기록
- 마지막에 **"이번 작업을 AI 활용 장면으로 기록할까요?"** 라고 묻는다. 특히 실패 후 수정한 장면이 있었다면 권한다. 원하면 `ai-log` 스킬을 실행한다.

## 규칙
- 각 에이전트에게 CLAUDE.md, 관련 `.claude/rules/`, `docs/planning/결정사항.md`를 먼저 읽도록 요청한다.
- 커밋은 하지 않는다(사용자가 요청할 때만).
