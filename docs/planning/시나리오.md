# 사용자와 하루 시나리오 — 만성질환자 복약·측정 기록 에이전트

- 과목: 생성형AI활용프로그래밍 기말 팀프로젝트
- 팀원: 안민영, 권현진
- 작성일: 2026-11-20
- 용도: 보고서 "사용자와 하루 시나리오" 1쪽 + 발표 시연 순서의 기준

> 모든 인물·처방·측정값은 **가상 데이터**입니다. 실제 개인정보는 수집하지 않습니다.

## 1. 사용자

**이○○ (67세, 가상 인물)**

- 고혈압 15년, 제2형 당뇨 8년, 심방세동은 작년에 진단
- 3년 전 배우자와 사별한 뒤 혼자 삶, 딸(가상 보호자)은 다른 도시에 삶
- 가정용 혈압계·혈당계·스마트워치 사용, 3개월마다 내과 진료
- 하는 말: "약을 먹었는지 안 먹었는지 헷갈려요", "병원에서 물어보면 잘 기억이 안 나요"

**문제**

1. 하루에도 여러 번 약과 측정을 챙겨야 한다.
2. 약을 먹었는지 헷갈려 두 번 먹을 위험이 있다. 특히 항응고제는 두 번 먹으면 출혈 위험이 있다.
3. 혼자 살아서 약을 놓쳐도 알아챌 사람이 없다.
4. 병원 예약 날짜와 진료 때 할 말을 기억에 의존한다.

**에이전트가 없으면:** 중복 복용 위험, 놓친 약을 아무도 모름, 진료 때 기억에 의존

## 2. 가상 처방 (아침 3종 · 저녁 2종)

| 시간 | 성분명 | 용도 | 시나리오 역할 |
|---|---|---|---|
| 아침 | 텔미사르탄 | 혈압 | "혈압 높은데 약 더 먹을까?" → 용량 판단 거절 |
| 아침 | 비소프롤롤 | 심박수·혈압 | 심박 기록과 연결 |
| 아침 | 리바록사반 | 심방세동 항응고 | 두 번 먹으면 위험 → 중복 체크 경고 + RAG 근거 |
| 저녁 | 메트포르민 서방정 | 혈당 | 저녁 식사와 함께 복용, 저녁 무응답 장면 |
| 저녁 | 아토르바스타틴 | 콜레스테롤 | 자몽주스 질문 (RAG) |

- RAG 문서: 위 5개 성분의 의약품안전나라 허가정보
- 처방 조합의 의학적 적절성은 판단하지 않는 가상 처방이다.

## 3. 알림 방식 (A안 확정)

| 알림 | 채널 |
|---|---|
| 본인 복약 알림 | Gradio 토스트 + 채팅창 메시지 + 디스코드 `#복약알림` |
| 보호자 알림 | 디스코드 `#보호자알림` (무응답 2회일 때만) |

- 실제 서비스라면 카카오 알림톡, 시연에서는 웹훅이 간단한 디스코드로 대체한다.
- 디스코드 발송이 실패해도 Gradio 알림은 뜨고, 실패는 로그에 남긴다.
- 메시지에는 최소 정보만 넣는다. 수치·약 이름·질환명은 넣지 않는다.
- 사용자는 **채팅창에 직접 입력**한다. 복약 버튼은 예비용이다.

## 4. 하루 시나리오 (11월 ○일, 진료 전날)

### 🌅 아침

**⓪ 07:10 병원 예약 안내 문자 → 캘린더 등록** · `도구 호출` `사람 승인`
- 병원 문자: "내일(○일) 오전 10시 ○○내과 진료 예약"
- 입력: "내일 10시 병원 예약 캘린더에 넣어 줘"
- 에이전트가 `add_calendar_event` 호출 전에 승인 버튼을 띄운다: "11월 ○일 10:00 '병원 진료'로 등록할까요? [등록] [취소]"
- 등록하면 전날 저녁과 1시간 전에 알림이 가게 설정
- 일정 제목은 "병원 진료"까지만 쓰고 질환명은 넣지 않는다.
- 네트워크 장애 시 `.ics` 파일로 대체

**① 07:30 혈압 측정 → 측정 오류 의심 → 재측정** · `MCP` `LangGraph(플로우 B, interrupt)`
- 계단을 올라온 직후에 재서 168/98 → 가상 측정기 MCP 서버에서 값 수집
- judge: 최근 2주 평균(약 132/84)과 차이가 너무 큼 → **측정 오류 의심**
- "5분 쉬었다가 다시 재 주세요" (interrupt로 대기)
- 재측정 138/86 → 목표 범위를 조금 넘음 → 저장한 뒤 LLM이 쉬운 말로 설명

**② 07:40 "혈압 높은데 약 하나 더 먹을까?"** · `도구 호출` `경계 테스트`
- 용량은 판단하지 않고 "약 용량은 의사·약사와 상의하세요"라고 안내
- 이 질문을 **진료 때 물어볼 질문 목록에 저장** → ⑨ 리포트로 이어짐

**③ 08:00 아침 약 알림 → "먹었어"** · `LangGraph(플로우 A)` `디스코드` `도구 호출`
- 가상 시계를 08:00으로 넘김 → Gradio 토스트 + 채팅창 메시지 + 디스코드 `#복약알림`
- 채팅 입력: "먹었어" → `check_medication` → 아침 3종 체크 (08:02 기록)

### ☀️ 낮

**④ 12:30 "점심에 자몽주스 마셔도 돼?"** · `RAG`
- `search_health_docs` → 아토르바스타틴 허가정보의 상호작용 부분
- "조금은 괜찮지만 많이 마시면 약 농도가 올라갈 수 있어요"를 출처 문서·쪽수와 함께 안내
- 어느 약인지 모호하면 되묻기 (모호 테스트)

**⑤ 13:00 "아침 약 먹었나?" / "아침 약 먹었어"** · `도구 호출` `RAG`
- 조회: `get_today_medications` → "08:02에 3종 모두 드셨어요"
- 헷갈려서 다시 "아침 약 먹었어"라고 입력하면:
  - `check_medication`이 이미 체크된 것을 보고 **다시 기록하지 않음**
  - "아침 약은 오늘 08:02에 이미 드신 걸로 기록돼 있어요. 또 드시면 안 돼요."
  - 리바록사반 허가정보의 "놓친 용량을 보충하려고 하루 용량을 두 배로 먹지 않는다" 근거 표시
- 보고서의 "최악의 오작동: 약을 두 번 먹음 → 방지책" 시연 장면

**⑥ 14:00 식후 2시간 혈당** · `MCP` `LangGraph(플로우 B)`
- 혈당 162 → 저장 → 범위 밖이라고 쉬운 말로 설명

**⑦ 15:20 워치 불규칙 리듬 알림** · `MCP` `규칙 엔진`
- `get_heart_rate`로 이벤트를 **기록만** 함. 부정맥 판단은 하지 않음
- 정해진 문구: "기록해 두었어요. 진료 때 보여 드릴게요. 가슴 통증이나 숨이 차면 바로 119에 연락하세요."

### 🌙 저녁

**⑧ 19:00 저녁 약 알림 → 무응답 → 보호자 알림** · `LangGraph(interrupt, 조건 분기)` `디스코드`
- 19:00 알림 (TV를 보느라 못 봄)
- 19:30 무응답 1회 → 재알림
- 20:00 무응답 2회 → 디스코드 `#보호자알림`: "저녁 약 확인이 안 됐어요" (모의)
- 딸이 전화 → 20:10 "먹었어" → **늦게 복용함**으로 기록

**⑨ 21:00 "내일 병원 가는데 정리해 줘"** · `도구 호출(make_report)`
- 2주치 진료 리포트 PDF
  - 맨 위: 내일 10:00 진료 일정 (⓪에서 등록)
  - 혈압·혈당·심박 통계와 그래프 (숫자는 코드가 계산)
  - 복약률: 놓침 0회, 늦게 복용 1회
  - 불규칙 리듬 이벤트 1건
  - 물어볼 질문 목록: ②의 혈압약 질문, ④의 자몽주스 (LLM은 문장만 다듬음)
- 리포트에 "가상 데이터" 표기
