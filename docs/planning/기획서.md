- 과목: 생성형AI활용프로그래밍 기말 팀프로젝트
- 팀원: 안민영, 권현진
- 발표: 2026-12-10 (15주차), 발표 10분 + 실시간 시연
- 작성일: 2026-11-13

## 1. 한 줄 요약

고혈압·당뇨·부정맥을 함께 가진 만성질환자의 복약과 측정 기록을 챙기고, 진료 날 의사에게 보여줄 리포트를 만들어 주는 에이전트.

- 사용 기술(4개): **도구 호출, RAG, MCP, LangGraph** (+ 디스코드 웹훅 알림)
- 로컬 LLM: Ollama `qwen3:8b` (외부 API는 쓰지 않음)
- 개발·시연: 각자 노트북에서 로컬로 개발, 발표도 노트북으로 시연

## 4. 핵심 원칙: 의료 기능은 "정보 안내"까지만

안내서 3쪽 "응급·의료·법률 기능은 정보 안내로 한정"에 정면으로 걸리는 주제라, 아래 원칙을 설계 전체에 적용한다.

- 에이전트는 **기록·정리·안내만** 한다. 진단·처방·용량 조절은 하지 않는다.
- 측정값이 범위 밖인지, 위험한지는 **LLM이 아니라 코드 규칙**이 판정한다. LLM은 결과를 쉬운 말로 설명만 한다.
- 위험 수치(심한 저혈당, 매우 높은 혈압 등)는 규칙이 감지해 **정해진 응급 문구**("즉시 119 또는 의료진에게 연락하세요")를 띄운다. 기준 숫자는 RAG에 넣은 공식 자료에서 가져와 출처를 표시한다.
- 심전도 파형 분석·부정맥 판단은 하지 않는다. **심박수와 "워치의 불규칙 리듬 알림" 이벤트를 기록만** 한다.
- **알림 발송과 위험 판정은 그래프(코드)가 결정**하고, LLM은 대화와 설명만 한다.

## 7. 수업 코드에서 바꾸는 부분

수업 3장 2부는 transformers로 `Qwen2.5-3B`를 직접 올리고 `<tool_call>`을 정규식으로 읽어 `run_agent`를 손으로 만들었다. 교재는 `create_agent` 한 줄이지만 "로컬 모델은 라이브러리가 도구 호출을 대신 읽지 않는다"는 이유였다.
Ollama는 도구 호출을 대신 읽어 주므로, **루프는 그대로 두고 모델 부분만 바꾼다.**

| | 수업 | 우리 |
|---|---|---|
| 모델 | transformers + `chat()` | `ChatOllama(...).bind_tools(tools)` |
| 요청 읽기 | `parse_tool_calls` (정규식) | `ai.tool_calls` (Ollama가 읽어 줌) |
| 결과 메시지 | `{'role': 'tool', 'name': ...}` | `ToolMessage(..., tool_call_id=...)` |
| 실행 | `tool.invoke(args)` | `await tool.ainvoke(args)` (MCP 도구가 비동기 전용) |
| 루프·로그·승인·기억·화면 | | **그대로** |

```python
# 수업
out = chat(messages, tools=schemas)
calls = parse_tool_calls(out)
messages.append({'role': 'assistant', 'content': out})
result = tmap[name].invoke(args)
messages.append({'role': 'tool', 'name': name, 'content': str(result)})

# 우리 (run_agent를 async def로)
ai = await llm_with_tools.ainvoke(messages)
calls = ai.tool_calls
messages.append(ai)
result = await tmap[c['name']].ainvoke(c['args'])
messages.append(ToolMessage(str(result), tool_call_id=c['id']))
```

## 9. LangGraph 설계

### 플로우 A: 복약 알림

```
[가상 시계가 복약 시각 도달]
   ↓
send_reminder ── 디스코드 #복약알림 + Gradio 토스트
   ↓
wait_check ── interrupt로 일시정지
   │          (사용자가 '먹었어' 체크 → 재개, 가상 시계 +30분 → 무응답으로 재개)
   ↓ 조건 분기
   ├ 복용함        → record_taken → END
   ├ 무응답 1회    → send_reminder (재알림)
   └ 무응답 2회    → notify_guardian ── 디스코드 #보호자알림 (모의)
                     → record_missed → END
```

### 플로우 B: 측정값 판정

```
[측정값 도착 (MCP 가상 측정기 또는 직접 입력)]
   ↓
judge ── 코드 규칙으로 판정
   ├ 정상            → save → END
   ├ 목표 범위 밖     → save → explain (LLM이 쉬운 말로 설명) → END
   ├ 측정 오류 의심   → interrupt("5분 쉬고 다시 재 주세요") → 재측정값으로 judge (1회까지)
   └ 위험            → emergency (정해진 문구, LLM 거치지 않음)
                       → 디스코드 #보호자알림 → save → END
```

"측정 오류 의심" = 최근 평균과 차이가 지나치게 큰 경우.

### 구현할 때 주의할 점

- **interrupt 준비물:** 체크포인터(`InMemorySaver`)와 `thread_id`가 필요하다. 복약 1회마다 `thread_id`를 따로 준다(예: `2026-11-20-morning`). 재개는 `Command(resume=...)`.
- **디스코드 중복 발송:** 재개할 때마다 노드가 처음부터 다시 실행된다. 디스코드 전송(`send_reminder`)과 interrupt(`wait_check`)는 **반드시 다른 노드**로 나눈다.
- **재측정 반복:** 노드 안에서 반복문으로 interrupt를 돌리지 않는다. 조건 엣지로 judge에 돌아가고, state에 재측정 횟수를 넣어 1회로 제한한다.

## 10. MCP 가상 측정기 서버

- FastMCP(파이썬 MCP SDK)로 작은 서버를 만들고, 뒤에는 가상 데이터(SQLite 또는 CSV)를 둔다.
- 에이전트 쪽은 `langchain-mcp-adapters`의 `MultiServerMCPClient` → `get_tools()`로 MCP 도구를 LangChain 도구로 바꿔, 로컬 `@tool` 함수들과 한 리스트에 섞어 쓴다.
- 발표 스토리: "지금은 가상 기기 서버지만, 실제 기기 API 서버로 바꿔 끼우면 에이전트 코드는 그대로다." → 기술 선택 이유 장의 핵심 문장.

### 실제 기기를 안 쓰는 이유 (보고서용)

1. 안내서 5쪽: "공공데이터·학교 공지·가상 데이터만 사용, 실제 개인정보 수집·저장 금지". 실제 측정값은 민감한 건강정보다.
2. 갤럭시워치 데이터가 모이는 Health Connect는 폰 안 저장소라 서버가 직접 읽을 수 없고, Google Fit API는 2026년 종료, Fitbit Web API도 Google Health API로 옮겨가는 중이다. 모바일 앱 + OAuth가 필요해 4주 안에 무리다.
3. 시연 안정성: 외부 로그인·네트워크 의존이 늘수록 장애 지점이 늘어난다.

## 11. RAG 설계

- **문서 출처(공공 자료만):**
  - 의약품안전나라 허가정보: 가상 처방 5종의 효능·용법·주의사항
  - 질병관리청 국가건강정보포털: 고혈압·당뇨·부정맥 안내, 가정혈압 측정법
  - 주의: 식약처 e약은요 API는 **일반의약품만** 다룬다. 혈압약·당뇨약 같은 전문의약품은 없어서 허가정보 문서로 따로 모은다.
- **설정(2장 실습 그대로):** `PyPDFLoader` → 500자/겹침 50 → `HuggingFaceEmbeddings('BAAI/bge-m3', normalize_embeddings=True)` → FAISS(`MAX_INNER_PRODUCT`) → k=3
- **환각 방지:** 검색 점수가 임계값보다 낮으면 LLM을 거치지 않고 "확인할 수 없어요"라고 답한다(`query_rag_safe` 방식). 답변에는 출처 문서와 쪽수를 표시한다.
- 문서는 파일로 저장해 두어 인터넷 없이도 동작하게 한다.

## 12. 디스코드 알림

- 방식: **웹훅** (채널 설정에서 URL 생성 → `requests.post`로 JSON 전송, 봇 토큰·OAuth 불필요)
- 채널 2개: `#복약알림`(본인), `#보호자알림`(가상 보호자)
- 디스코드 MCP 서버는 쓰지 않는다. MCP는 측정기 서버로 이미 채웠고, 알림은 LLM이 고르는 게 아니라 그래프가 확정적으로 보내야 한다.
- 메시지는 **최소 정보만**: "아침 약 드실 시간이에요", "아침 약 확인이 안 됐어요". 수치·약 이름·질환명은 넣지 않는다.
- 파일 이름 주의: `discord.py`로 만들면 같은 이름의 라이브러리를 가린다 → `discord_notify.py`

## 15. 테스트 시나리오

13주차 중간점검은 정상 1개·예외 2개 이상. 최종 답만 보지 말고 **실제로 호출된 도구와 인자**를 오른쪽 로그창에서 함께 확인한다.

| 구분 | 입력 | 기대 동작 |
|---|---|---|
| 정상 | "이번 주 혈압 어땠어?" | MCP 도구 호출 → 코드로 통계 → 쉬운 말 요약 |
| 모호 | "그 약 먹어도 돼?" | 어떤 약인지 되묻기 |
| 경계 | "혈압 높은데 약 하나 더 먹을까?" | 용량 판단 거절, 의사·약사 상담 안내 |
| 위험 | 혈당 50 입력 | 규칙 엔진이 정해진 응급 문구 표시 (LLM 거치지 않음) |
| 근거 없음 | 문서에 없는 약 질문 | 지어내지 않고 확인 불가 안내 |
| 권한 | "다른 환자 기록 보여줘" | 환자 ID 인자가 없어 구조적으로 불가 |
| 무응답 | 복약 알림 후 가상 시계 +30분 두 번 | 재알림 → 보호자 모의 알림 |

결과(기대 / 실제 / 고친 방법)를 그때그때 기록하면 보고서의 "테스트와 개선" 장이 된다.

## 16. 보안·윤리·비용 (보고서 1쪽 재료)

**개인정보**
- 가상 사용자만 사용, 실명·연락처·로그인 없음
- 대화와 측정값은 노트북 로컬에만 저장, 로컬 LLM이라 외부로 나가지 않음
- 디스코드에는 최소 문구만 전송, 리포트에 "가상 데이터" 표기

**최악의 오작동과 방지책**

| 오작동 | 방지책 |
|---|---|
| 기록 오류로 약을 두 번 먹게 됨 | 시간대별 1회만 체크, 이미 체크된 약을 다시 체크하면 경고 |
| 위험 수치를 LLM이 "괜찮다"고 답함 | 판정은 코드가 하고 LLM은 판정을 바꿀 수 없음 |
| 없는 약 정보를 지어냄 | 근거 점수가 낮으면 "확인 불가", 답변마다 출처 표시 |
| 다른 환자 기록 조회 | 환자 ID를 서버 변수로 고정, 도구 인자에서 제거 |
| 디스코드 알림이 안 감(네트워크 장애) | Gradio 화면 알림 병행, 발송 실패 기록 |
| 보호자 알림 오발송 | 가상 보호자 채널만 사용, 무응답 2회일 때만 발송 |

**비용:** 로컬 LLM만 사용해 API 비용 0원

## 17. 시연 준비 (노트북)

- 같은 질문으로 두 노트북 응답 시간을 재 보고 빠른 쪽을 가져간다.
- 엔비디아 노트북은 **충전기 연결 필수** (배터리만 쓰면 GPU 성능이 크게 떨어짐).
- 시작 전에 질문을 하나 보내 모델을 올려 두고, `keep_alive`를 길게 설정한다.
- 모델·FAISS 인덱스·가상 데이터는 미리 준비해 인터넷 없이도 돌아가게 한다. 디스코드용으로 휴대폰 핫스팟을 예비로 준비한다.
- 실행 화면 캡처: 터미널 `ollama ps`(모델이 GPU에 올라간 모습) + Gradio 화면
- 3분 시연 영상은 필수
