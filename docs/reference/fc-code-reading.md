## 1부 ReAct 셀 구조 (참고)
- **4단계 도구 3개** (슬라이드 54~): ① `create_retriever_tool`로 검색기→도구(설명 = 무엇을+언제+언제 아닌지) ② `@tool` 계산기(허용 문자 검사 후 `eval`, 오류는 문장) ③ `tools`(프롬프트용 목록) + `tool_map`(이름→도구).
  - 확인 셀: 에이전트에 붙이기 전 **사람이 먼저 호출**(정상 입력 + 위험한 입력 `import os` → `[계산 오류]` 문장).
- **5단계 프롬프트** (69~): 역할+도구 목록 / 출력 형식 / 가드레일 / 질문+scratchpad / `PromptTemplate`(빈칸 4개: `tools`, `tool_names`, `input`, `agent_scratchpad`).
- **6단계 렌더링** (79~): `format_tools()` → `render_prompt()`. **LLM이 실제로 받는 글을 눈으로 확인.**
- **7단계 LLM 호출+파서** (85~): 상수 `STOP`, `OBS_MAX` / `ask_react()` / 정규식 3개 / `parse()`(도구 호출·최종 답변·형식 위반) / `shorten()`(1,200자). 확인 셀: **가짜 LLM 출력으로 파서만 assert 테스트**(LLM 없이).
- **8단계 `run_react`** (101~): 머리+준비 → [1]생각 [2]파싱 → [3]분기(형식 위반이면 안내문 붙이고 다시 / 답이면 return) → [4]행동+관찰(없는 도구·오류도 문장) → 한도 초과.
- 9-5 실험: 같은 검색기에 이름 `tool_a/b`, 설명 "정보를 제공합니다."로 바꿔 **도구 선택이 흔들리는 것**을 비교.
- 10단계: `ConversationManager`(history 튜플 리스트 + `max_turns`) → Gradio(왼쪽 채팅 2 : 오른쪽 로그창 1).

## 우리 프로젝트에 적용할 점
- 우리 `run_agent`는 **15-1의 일곱 덩어리 순서 그대로**(시스템 프롬프트 → `NEED_APPROVAL` → 준비 → 모델 호출/최종 답 → 실행·tool 메시지 → 한도 → 한 번 실행). 바뀐 곳은 모델 호출 두 줄(`ainvoke`)과 메시지 형식(`ToolMessage`)뿐이라고 발표 때 말할 수 있다.
- 우리 `agent/memory.py` = 15-2(`keep=12`), `app.py` = 16-1(왼쪽 상담 / 오른쪽 도구 로그 + 승인 버튼·토스트·가상 시계), 권한 구조 = 17-2(`config.PATIENT_ID`), `add_calendar_event` 승인 = 17-3.
- 에이전트에 붙이기 전 **사람이 먼저 `.invoke()`로 4경우 확인**(14 확인), 파서 같은 부품은 **LLM 없이 assert 테스트**(7단계 확인) — 우리 `tests/`가 이 방식(LLM 호출은 모킹/마커).
- 날짜는 `TODAY`/`day(±n)` 같은 **오늘 기준 상대 날짜**로 시드 데이터를 만든다(`db/seed_fake_data.py`). 고정 날짜는 시간이 지나면 조용히 깨진다.
