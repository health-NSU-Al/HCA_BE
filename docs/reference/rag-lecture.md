- 출처: `docs/lectures/02장_RAG_강의자료_4주차_공유버전.pdf` (90쪽, 학교 GPU 서버 실습 슬라이드). 슬라이드 번호는 하단 번호 기준.
- 이 요약은 **개념·결과 읽는 법** 위주다. 코드 구조(6~10단계)와 임계값은 `rag.md`, 응용 문제는 `rag-exercises.md`에 있다.
- 서버 세팅(conda `myenv`, 커널, 포트 7860+학번 등)은 학교 GPU 서버용이라 **우리와 무관**하다. 우리 노트북 개발에는 쓰지 않는다.

## RAG란 (슬라이드 21, 36)
- **검색(Retrieval) → 증강(Augmented) → 생성(Generation).** LLM은 학습한 것만 안다. 우리 문서 내용으로 답하려면 찾아서 함께 넣어 준다. 비유: 오픈북 시험.
- 왜: 환각 감소 / 최신·내부 정보 / **출처(몇 쪽)를 보여줄 수 있음**.
- 관련 문서가 없으면 RAG도 엉뚱한 근거로 답한다(3주차 사례: 문서 3개일 때 엉뚱한 문장이 0.15점으로 선택됨) → **점수 기준선**이 필요(`rag-exercises.md`).
- **사전 준비(한 번)**: 문서 → 청크 → 임베딩 → 벡터 DB 저장 / **질문마다**: 질문 임베딩 → 상위 k 검색 → 컨텍스트+질문 → 프롬프트 → LLM → 답+출처.
- 300쪽 PDF를 통째로 LLM에 안 넣는 이유: 입력 길이 한계·비용·정확도.

## 용어
- 임베딩: 문장 → 숫자 목록(벡터). 코사인 유사도: 두 벡터의 **방향** 비교(−1~1, 클수록 비슷). 청크: 문서를 자른 조각. Loader: PDF → Document. 벡터 DB: Chroma·FAISS. 검색기(retriever): 질문 → 관련 청크 k개. 프롬프트 템플릿: `{context}` `{question}` 빈칸.

## PDF Loader 3종 (슬라이드 38)
| 로더 | 특징 | 교재 측정(445쪽) |
|---|---|---|
| PyPDFLoader | 기본, metadata 단순 | 15.5초 |
| PyMuPDFLoader | **가장 빠름**, metadata 풍부(파일 경로·총 쪽수) | 2.4초 |
| PDFPlumberLoader | 표·배치에 강함, 가장 느림 | 30.5초 |
- Document = `page_content`(본문) + `metadata`(`source`, `page`, `total_pages`, `page_label`). **`page`는 0부터**, 뷰어 쪽수는 +1 → 출처 표시는 `page + 1`.
- 한국어 PDF가 깨지거나 표가 많으면 로더를 바꿔 본다(우리 허가정보 PDF는 표가 많을 수 있다).

## 청킹 (슬라이드 47~49)
- `RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)`: 문단→줄→문장→글자 순으로 경계를 찾아 자른다(그래서 길이가 딱 500이 아님). 겹침이 있으면 청크 수가 늘지만 **경계에 걸린 설명이 양쪽에 남아 검색 누락을 막는다.**
- chunk_size를 너무 줄이면(예: 100) 용어와 설명이 다른 청크로 갈라져 오히려 답을 못 만든다. **500~1000자가 흔한 출발점.**
- `SemanticChunker`: 길이가 아니라 **의미가 바뀌는 곳**에서 자른다(인접 문장 거리가 기준값 이상). 방식 3가지: `percentile`(95), `standard_deviation`(3), `interquartile`(1.5). 문장마다 임베딩해서 **느리다** → 큰 문서 전체에는 쓰지 않는다. (우리는 Recursive 500/50으로 충분.)

## 검색 결과·점수 읽기 (슬라이드 35, 55~56)
- 검색은 **항상 k개를 돌려준다**("오늘 날씨 어때"에도 3개, 점수만 낮을 뿐).
- 점수가 음수이거나 1을 넘으면 거리 옵션(cosine / MAX_INNER_PRODUCT)이 빠진 것.
- **"점수 0.62면 관련 있나?" → 절대 기준은 없다.** 같은 DB 안에서 상대 비교하고 기준선은 실험으로 정한다.
- **셀 재실행 함정**: `persist_directory`가 있으면 같은 폴더에 **추가 적재**된다(count가 900 → 1800 → 2700). 인덱스 만드는 코드는 한 번만, 다시 만들 때는 폴더를 지우고(`shutil.rmtree`) 시작. 검색 결과에 같은 청크가 두 번 나오면 이 문제.

## 문서 정리와 검색기 (10단계)
- 머리말·목차·판권 쪽을 빼고 본문만 넣는다(`texts[13:-1]` 식 슬라이싱). 어디까지가 목차인지는 앞뒤 쪽을 **직접 출력해 확인**한다.
- `as_retriever(search_kwargs={"k": 2})`. k를 바꾸려면 `search_kwargs`만 수정.
- 항목 설명이 2~3쪽에 걸치면 k가 작을 때 뒷부분이 잘린다. k를 늘리면 프롬프트가 길어져 느려진다.

## query_rag (12단계)
- 템플릿은 **역할 + 규칙("검색 결과에 없는 내용이면 답변할 수 없다고 하세요") + `{context}` + `{question}`**. 템플릿 안에 다른 중괄호가 있으면 `KeyError` → `{{ }}`로 두 번.
- 반환은 `{'query', 'result', 'source_documents'}` — **근거 문서를 같이 돌려줘야** 출처를 표시할 수 있다.
- 확인 1: `prompt.format(...)`을 직접 출력해 **LLM에 실제로 들어간 글**을 본다. 확인 2: 문서에 없는 질문("오늘 저녁 뭐 먹지?")에 어떻게 답하나 — **소형 모델은 프롬프트 규칙을 무시하고 답하기도 한다 → 코드로 막아야 한다(점수 기준선).**
- 문서를 주는 이유(모델이 이미 아는 질문이라도): ① 정의가 "우리 문서 기준"으로 통일 ② 출처를 댈 수 있음 ③ 모델이 모르는 항목을 다룸.

## 내 문서로 교체 (응용 3 — 팀프로젝트의 씨앗)
- 바꿀 곳은 **문서 경로 / 저장 폴더 이름 / 템플릿 페르소나** 세 군데뿐. 저장 폴더 이름을 다르게 해야 다른 인덱스와 섞이지 않는다. 짧은 문서는 `chunk_size=200` 정도로.

## 우리 프로젝트에 적용할 점
- 템플릿 규칙에 "검색 결과에 없으면 확인할 수 없다고 하세요"를 넣되 **그것만 믿지 않고** 점수 임계값으로 LLM 호출 전에 차단한다(절대 원칙).
- 허가정보 PDF는 로더 2~3종으로 한글·표가 깨지지 않는지 먼저 비교한다. 표지·목차·부록 쪽 제외 여부를 직접 출력해 확인한다.
- 인덱스는 한 번만 만든다. 다시 만들 때 `rag/index/`를 지우고 시작한다(중복 적재 방지).
- 답변마다 `source_documents`의 `page + 1`로 **문서명·쪽수**를 붙인다.
- 정확한 질문 셋(있는 약 / 없는 약 / 모호한 약)으로 임계값을 정하고 기록한다(`docs/test-log.md`).
