# 참고: RAG 응용 문제 1·2·3 (k · 점수 기준선 · 내 문서)

- 출처: `docs/lectures/02장_RAG 전반 _응용문제 1,2,3.pdf` (코랩 버전, PART 5 · 슬라이드 68~82). 앞부분(6~13단계)은 `rag.md`·`rag-lecture.md`와 겹쳐서 **응용 문제와 자주 나는 오류만** 정리했다.
- 이 응용 2가 우리 프로젝트 `search_health_docs`의 임계값 안전장치의 원형이다.

## 응용 1 — 검색 개수 k를 바꾸면 (슬라이드 69~71)
- k=1, 2, 4(마지막에 원래 값으로 복원)로 같은 질문을 묻고 **답 글자 수 / 근거 쪽수(+1) / 걸린 시간**을 비교한다.
- 결과: k가 커지면 근거 쪽이 늘고 **프롬프트가 길어져 느려지며 답이 산만**해질 수 있다. **검색이 틀린 질문은 k로 못 고친다.**
- "더 많이 찾으면 더 좋은가?" → 아니다. 우리는 k=3에서 시작해 질문 세트로 확인한다.

## 응용 2 — 점수 기준선 `query_rag_safe` (슬라이드 72~75)
- **환각은 규칙 문장의 선의가 아니라 코드로 막는다.**
```python
def query_rag_safe(question, threshold=0.4):
    pairs = vectordb.similarity_search_with_score(question, k=3)   # FAISS(MAX_INNER_PRODUCT)라 점수 = 코사인
    best = max(float(s) for _, s in pairs)
    if best < threshold:                                           # 기준선 미만 → LLM을 부르지 않는다
        return {"result": f"관련 문서가 없어서 답변할 수 없어 (최고 점수 {best:.2f})", "source_documents": []}
    ...                                                            # 이후는 query_rag 본문 그대로
```
- 시험 3종: 문서에 있는 질문('디커플링') / **문서에 없는 질문('오늘 점심')** / 경계 질문('GDP'). 점심은 "답변할 수 없어 (최고 점수 0.2x)", GDP는 정답이 나와야 한다.
- 기준선을 0.3·0.5로 바꿔 보고 적당한 값을 고른다: **너무 높으면 진짜 질문도 막히고, 너무 낮으면 헛소리가 통과한다.** 문서에 없는 질문도 점수가 0.3 근처까지 나올 수 있으므로 **기준선은 실험으로 정한다.**
- FAISS는 `similarity_search_with_score`(점수 = 코사인, 클수록 비슷), Chroma는 `similarity_search_with_relevance_scores`. 사용하는 함수의 점수 방향을 한 번 출력해서 확인한다.

## 응용 3 — 내 문서로 바꾸기 (슬라이드 76~79)
- 로더 / 저장소 / 페르소나 **세 개만 교체**: `TextLoader`로 읽어 200자·겹침 20으로 자르고, 새 FAISS 저장소(`faiss_mine`)와 `retriever2`·`prompt2`·`query_mine`을 만든다(변수 이름을 안 바꾸면 기존 것과 섞인다).
- 확인: 문서에 없는 학과 소개는 **거절**(영어로 답하면 "한국어로"를 추가), 문서에 있는 내용은 파일 내용으로 답.
- 수업 과제: 다음 주까지 RAG 코드 전체 + 응용 1·2·3 + 자기 문서(AI·개발자 관련, 최소 20쪽 이상) — 제출 기준이라 우리 프로젝트와는 별개.

## 자주 나는 오류 (슬라이드 81, 검증 중 실제로 난 것)
| 증상 | 원인 → 조치 |
|---|---|
| `FileNotFoundError …/data/data/` | 경로 `/data`가 두 번 붙음 → 기본 경로 수정 |
| FAISS 파일 없음 | 현재 폴더가 다름 → 작업 폴더 확인 |
| 저장된 조각이 352가 아니라 339 | 슬라이싱을 두 번 함 → 처음부터 다시 |
| `NameError: docs0`/`Chroma` | 재시작 후 정의 셀을 안 돌림 → 위에서부터 다시, "한 번만" 셀은 확인 셀만 |
| 셀을 다시 돌리면 개수가 2배 | `persist_directory`에 추가 적재 → 폴더를 지우고 다시 |

## 우리 프로젝트에 적용할 점
- `rag/search.py`에 `search_safe` 형태로 임계값 분기를 둔다. 임계값은 수업의 0.4가 아니라 **bge-m3 + 우리 허가정보**로 "있는 약 / 없는 약 / 모호한 약" 질문을 돌려 정한다. 후보값별 결과표를 `docs/test-log.md`에 남기면 보고서의 "테스트와 개선" 재료가 된다.
- 반환에 `source_documents`(문서명, `page+1`)를 포함해 출처·쪽수를 표시한다.
- 시연 장면 ④(자몽주스)가 통과하고, 문서에 없는 약은 "확인할 수 없어요"가 나오는 값을 고른다(기획서 15장 "근거 없음").
